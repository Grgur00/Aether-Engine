Training Artifact Identity and Storage Policy Functions

Function index | Python and training cache | Cache operations

This reference covers five Java source files: TransformationFingerprint, CacheKey, CacheEntry, TrainingCacheStoragePolicy, and TrainingCacheDurability. These define an artifact's identity, caller-byte ownership, representation selection, and persistence mode. They do not determine whether a Python transform is actually deterministic or whether its descriptor contains every relevant input.

Reuse Architecture

An artifact is addressed by namespace + sample ID + transformation fingerprint. The database key stores a readable namespace prefix followed by a SHA-256 digest of the complete identity. Changing the sample identity or transform fingerprint produces a different lookup key; version labels alone are not Java cache identity.

Boundary Responsibility
Dataset/application Supply stable sample IDs and descriptors that change whenever deterministic preprocessing output changes
TransformationFingerprint Convert supplied descriptor information into 32 identity bytes
CacheKey Combine namespace, sample identity and fingerprint into a storage key
CacheEntry Copy caller payload bytes for batched publication
TrainingCache Validate stored envelopes and reject conflicting bytes for a currently existing immutable key

The sample ID is not automatically a source-content checksum. If a caller reuses the same ID/fingerprint after changing source content, Java lookup can return the previous artifact. Likewise, hashing a supplied descriptor does not discover undeclared library versions, random state, file changes, or transform parameters.

TransformationFingerprint Functions

Source: TransformationFingerprint.java.

Construction and Canonical Descriptors

Function Behavior
Private TransformationFingerprint(digest) Retains the supplied array directly; factory paths provide a fresh digest or defensive copy. The constructor itself performs no length check.
ofCanonicalDescriptor(descriptor) Requires a non-null string, encodes it as UTF-8 and hashes those exact bytes. Empty strings are allowed. It does not parse or normalize the descriptor.
of(descriptor) Requires a map, rejects null keys/values, converts values with String.valueOf, sorts keys with TreeMap, constructs a length-delimited string, then delegates to ofCanonicalDescriptor.
fromBytes(digest) Requires exactly 32 non-null bytes and clones them; accepts any 32-byte value, not only one generated by these factories.

For each sorted entry, of appends:

<key-character-count>:<key><value-character-count>:<value>;

Counts come from Java String.length() (UTF-16 code units), then the complete string is encoded as UTF-8 for hashing. This is a Java-specific flat descriptor format, not canonical JSON. Nested objects, maps and collections receive their toString representation, not recursive canonicalization. An integer value 1 and string value "1" therefore produce the same string value in this factory. Cross-language clients must agree on bytes rather than assume all descriptor canonicalization APIs implement this exact format.

Ownership, Equality and Rendering

Function Behavior
bytes() Returns a clone of the stored digest. Caller mutations cannot change identity.
equals(other) Checks type and Arrays.equals on digest contents; not a constant-time authentication check.
hashCode() Uses Arrays.hashCode on digest contents, consistent with equality.
toString() Formats each digest byte as two lowercase hex digits, producing 64 characters; does not expose the array.

Hash and Key Helpers

Function Behavior
sha256(input) Creates a new SHA-256 digest instance and hashes the whole array. Unavailable algorithm becomes IllegalStateException with cause.
sha256(input, offset, length) Creates a new digest, updates from the specified range, then returns 32 bytes. Range validity comes from the digest API, not custom argument checks.
keyBytes(namespace, sampleId, transform) UTF-8 encodes namespace/sample ID, allocates a length-prefixed identity buffer, includes the transform's internal digest, and returns its SHA-256.

The keyBytes preimage is big-endian:

Field Width
Namespace UTF-8 byte length 4 bytes
Namespace bytes Declared length
Sample ID UTF-8 byte length 4 bytes
Sample ID bytes Declared length
Transformation fingerprint 32 bytes

Unlike of's descriptor counts, these lengths count UTF-8 bytes. There is no separate maximum namespace/sample length here; ordinary integer/allocation limits still apply. The helper relies on validated callers for non-null identity fields.

CacheKey Functions

Source: CacheKey.java.

CacheKey(namespace, sampleId, transform) requires all three fields, rejects a blank namespace and an empty sample ID. A whitespace-only sample ID is allowed. It does not trim, normalize Unicode, canonicalize a path, or hash source content. Implicit record accessors return immutable fields; generated record equality uses string equality and TransformationFingerprint.equals.

Package-private storageKey() allocates a new array containing:

4-byte big-endian namespace UTF-8 length
namespace UTF-8 bytes
32-byte keyBytes(namespace, sampleId, transform) digest

The namespace is both directly recoverable and included in the digest preimage. The sample ID and fingerprint cannot be recovered from this key; consumers that need them must retain the original identity elsewhere. Repeated calls allocate and hash again; the key record does not cache its encoded representation.

CacheEntry Functions

Source: CacheEntry.java.

Function Behavior
CacheEntry(key, value) Requires both fields and clones the input array. Empty payloads are allowed.
Overridden value() Returns another clone on every call.
Implicit key() Returns the immutable key.

This prevents publication from borrowing a mutable caller array. TrainingCache.putMany takes one value() copy per supplied entry and retains that owned copy internally for length checks and encoding. Record-generated equality does not compare array contents; publication explicitly uses Arrays.equals when checking payload conflicts.

Storage Representation Policy

Source: TrainingCacheStoragePolicy.java.

Function Behavior
TrainingCacheStoragePolicy(mode, segmentThresholdBytes) Requires non-null mode and positive threshold, even when that mode does not use a threshold.
auto() Returns AUTO with the cache's 256 KiB threshold.
inline() Returns INLINE with Integer.MAX_VALUE; inline selection comes from mode, not comparing to this threshold.
segment(thresholdBytes) Returns SEGMENT with the supplied positive threshold.
usesSegment(payloadBytes) True for all SEGMENT payloads, or for AUTO payloads at least the threshold; always false for INLINE. No payload-length argument validation.

Mode contains AUTO, INLINE, and SEGMENT. In particular, SEGMENT mode forces every value into a segment; segment(largeThreshold) does not mean "segment only values above that threshold." Only AUTO uses the threshold for selection. At exactly 256 KiB the default AUTO policy selects a segment.

The policy does not create a segment directory or ensure persistence. An ephemeral cache has no segment store, so a value selected for segment representation fails publication rather than silently changing policy.

Durability Mode

Source: TrainingCacheDurability.java.

Enum value Current cache behavior
EPHEMERAL Opens an in-memory database and creates no segment store; does not survive reopen.
RECOVERABLE Opens persistent storage, uses GROUP_SYNC writes and publishes segments without explicit file/directory force.
DURABLE Uses SYNC database writes and requests segment file/directory force where supported.

These are actual selections made in TrainingCache.open and putMany, not a universal hardware guarantee. Segment directory synchronization is skipped on Windows, and publication failure/cleanup boundaries are described in the cache operations reference. This enum has no explicit method declarations.

Tests and Coverage Limits

TrainingCacheTest checks changed-transform misses, reopen, conflicting immutable writes, duplicate publication, competing writers, ephemeral reopen, policy representation and caller array independence. These examples do not prove descriptors are complete for every transform or that all Python identity formats equal Java's flat-map format.

The declaration inventory checks every explicit function name in these five files. Daemon parsing, Python identity construction, offline bulk publication, and cache operations are separate coverage areas.
