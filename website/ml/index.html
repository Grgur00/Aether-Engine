Aether for machine learning

Prepare once.
Train again.

Reuse deterministic preprocessing across epochs and experiments. Keep your training loop in Python, with derived artifacts stored by the local Java engine.

Aether can reduce time spent waiting for input. It does not change the model’s GPU computation. The benefit depends on whether decoding, tokenization or preprocessing is limiting your training throughput.

Source + transformContent identity
→
Aether lookupHit: reuse · miss: compute
→

→
GPU trainingYour existing model

Use it for reusable token IDs, resized images, features, or other reproducible intermediate arrays. Keep random crops, masking and other stochastic augmentation after the cache unless their complete random state is part of the key.

Start small

The example below needs no GPU or dataset download. It exercises the real Java cache using four generated images. It demonstrates reuse, not a speedup claim. The training cache is experimental; retain your authoritative raw data.

01

Two terminals

Start the cache.

You need Git, JDK 21 and Python 3.10 or newer. The Gradle wrapper builds the Java daemon; the Python client is installed from the same source checkout. Run the commands below from the repository root. Installing PyTorch is only necessary for the later training integration.

Clone · any terminal
git clone https://github.com/Grgur00/Aether-Engine.git
cd Aether-Engine

Windows PowerShell

Terminal 1 · install and start Java
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e clients/python
.\gradlew.bat :modules:aether-training-cache:trainingCacheDaemon -PcacheDir=build/ml-cache -Pport=9484 --console=plain

Linux / macOS Bash

Terminal 1 · install and start Java
python3 -m venv .venv
.venv/bin/python -m pip install -e clients/python
./gradlew :modules:aether-training-cache:trainingCacheDaemon -PcacheDir=build/ml-cache -Pport=9484 --console=plain

Leave this terminal running. Once the daemon prints its listening port, Python can connect at 127.0.0.1:9484. The directory belongs to the Java daemon; do not start another daemon against the same directory.

Choose your shell

PowerShell commands use Windows paths. Bash commands use Unix paths. All commands here are single lines; no shell-specific continuation characters are needed. Kaggle’s /kaggle/... paths exist only inside Kaggle.

02

Check reuse before training

Your first cache hit.

The complete example is included in your checkout at website/ml/ml_cache_example.py. It creates four PNGs, resizes them to 64 × 64 RGB arrays, and makes two passes through Aether.

Terminal 2 · Windows PowerShell
.\.venv\Scripts\python.exe website/ml/ml_cache_example.py
Terminal 2 · Linux / macOS Bash
.venv/bin/python website/ml/ml_cache_example.py

With a fresh cache, expect:

Expected output · fresh cache
epoch 1: hits=0, misses=4, shape=(3, 64, 64)
epoch 2: hits=4, misses=0, shape=(3, 64, 64)

Run it again: both passes should hit. Use --image-dir path/to/images to try your own PNG or JPEG directory, or --port 9485 to match a different daemon port. For acknowledged writes to survive stopping and restarting the daemon, use the explicit durable launch commands below.

The core operation is explicit: a miss computes and stores bytes; a hit reuses those bytes. Aether does not call your preprocessing function automatically.

Read-through pattern · Python
from aether_training_cache import (
    AetherTrainingCache, CacheKey, TransformationFingerprint,
)

transform = TransformationFingerprint.from_mapping({
    "tokenizer": "example-tokenizer-v1",
    "max_length": 512,
    "implementation": "my-preprocessing-v1",
})
# source_sha256 must describe the current immutable source content.
key = CacheKey("my-training-data", source_sha256, transform)

with AetherTrainingCache(port=9484) as cache:
    payload = cache.get(key)
    if payload is None:
        payload = preprocess_and_encode(source_bytes)  # your function
        cache.put(key, payload)
    sample = decode(payload)  # your function

This pattern is illustrative; use the downloadable example for a complete program. It serializes arrays with NumPy, disables pickle loading, and returns owned, writable arrays for subsequent tensor operations.

03

Correct reuse

Make changes visible.

A cache key combines a namespace, a sample identifier, and a transformation fingerprint. In this guide, the sample identifier is a SHA-256 digest of the source bytes. The fingerprint describes the deterministic preprocessing and its output format.

What changes?What should happen?
Sample order or epochKeep the same key. Reuse the artifact.
Image or text contentRecompute the source digest. The changed sample gets a new key.
Resize, normalization or tokenizerChange the fingerprint, including any model/tokenizer revision and vocabulary.
Code or encoding changesBump the implementation/output version. Include library versions when they can change results.
Dataset V1 → V2Keep keys stable for unchanged samples. Only new or changed content needs new artifacts.

Hash and validate source files once when building an immutable dataset manifest. The example’s index_images does this outside the epoch loop. Do not edit those files while that index is in use; rebuild it after changes. A cache hit does not re-read the original source to detect an edit.

For image/mask pairs, include both hashes in the sample identity. For text, include everything that affects token IDs. Avoid adding a whole-dataset version to every key if you want unchanged samples to survive a dataset update.

04

Keep your model

Connect to PyTorch.

Install the PyTorch build appropriate for your hardware using PyTorch’s installation instructions. Then use the example’s functions in a Dataset. This starting point uses one loader process; no GPU is required just to iterate it.

Dataset integration · run from repository root
import sys
sys.path.insert(0, "website/ml")

import torch
from torch.utils.data import Dataset, DataLoader
from aether_training_cache import AetherTrainingCache
from ml_cache_example import index_images, cached_image

class CachedImages(Dataset):
    def __init__(self, image_dir):
        self.samples = index_images(image_dir)
        self.cache = AetherTrainingCache(port=9484)

    def __len__(self):
        return len(self.samples)

    def __getitem__(self, index):
        array, _ = cached_image(self.samples[index], self.cache)
        image = torch.from_numpy(array)
        # Apply random augmentation here, after cache retrieval.
        return image

dataset = CachedImages("build/ml-guide-images")
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
loader = DataLoader(dataset, batch_size=16, shuffle=True,
                    num_workers=0, pin_memory=device.type == "cuda")
try:
    for epoch in range(2):
        for images in loader:
            images = images.to(device, non_blocking=device.type == "cuda")
            # Feed images and your labels into your existing training step.
            print(epoch, images.shape, images.device)
finally:
    dataset.cache.close()

The example returns only images. Join labels or masks from your dataset before using it for supervised training. If you enable worker processes, create a separate client lazily inside each worker and use the usual if __name__ == "__main__" guard. Do not share an already-connected client across a fork or pickle it into spawned workers.

For higher throughput, investigate get_many, get_many_values and put_many to amortize request overhead. Measure your batch sizes. Advanced segment mapping requires local shared access to segment files and careful view lifetimes; the byte-based example avoids that complexity. CPU mapping does not remove the copy to GPU memory.

05

Measure the complete loop

Does the GPU wait less?

Aether is useful when reusing preprocessing saves more time than lookup, serialization, and cache writes cost. If GPU compute already dominates, input caching may barely change total training time. A low lookup latency alone is not evidence of faster training.

Compare againstQuestion answered
Raw recomputationDoes reuse improve training samples per second?
Pre-materialized mmapWhat overhead does on-demand admission and retrieval add versus prepared data?
RAM-ready inputsHow close is training to an input-ready reference? GPU compute and run noise can hide differences.
  • Keep the model, batches, precision, sample order and augmentation policy comparable.
  • Measure first-pass misses, warm epochs, and a dataset update separately.
  • Report total training wall time, samples/second, input waiting, GPU utilization, and cache hit/miss counts.
  • Report preparation cost, memory and storage use separately; say clearly which costs the throughput denominator includes.
  • Use repeated paired runs and rotate backend order. Preserve failed runs and correctness checks.

The four-image walkthrough is not a benchmark. For the repository’s real training harness, inspect the GPU segmentation runner and paired campaign driver. No universal GPU speedup is claimed by this guide.

06

Local ownership

Keep the cache reusable.

  • Keep the same cache directory across epochs and restarts. Store it on local disk with enough free space for artifacts and temporary storage work.
  • Keep the Java daemon running while Python workers use it; the client is not the storage engine.
  • The Gradle daemon command uses RECOVERABLE mode, which does not force each acknowledged publication to disk. Stopping a process is not a substitute for an explicit durability mode.
  • Keep raw data authoritative. Treat derived artifacts as reproducible cache data, and plan disk usage as content and transform versions accumulate.
  • Stop all clients and the daemon before retiring a cache directory. Never modify live storage files by hand.

Durable writes across restarts

Stop the earlier daemon before using these commands. This launches a separate cache at build/ml-cache-durable with a 1 GiB cache byte limit and DURABLE publications. Run the example, stop Java, restart this same command and run the example again: unchanged samples should hit. Allow additional disk space for storage overhead and temporary files.

Windows PowerShell · explicit durable daemon
.\gradlew.bat :modules:aether-training-cache:paperRuntimeClasspath --console=plain
java --enable-preview -cp (Get-Content modules/aether-training-cache/build/paper-runtime-classpath.txt -Raw).Trim() io.aetherdb.training.cache.TrainingCacheDaemon build/ml-cache-durable 9484 1073741824 DURABLE
Linux / macOS Bash · explicit durable daemon
./gradlew :modules:aether-training-cache:paperRuntimeClasspath --console=plain
java --enable-preview -cp "$(cat modules/aether-training-cache/build/paper-runtime-classpath.txt)" io.aetherdb.training.cache.TrainingCacheDaemon build/ml-cache-durable 9484 1073741824 DURABLE
Which Python API?

This guide uses AetherTrainingCache, which talks to the Java daemon. The repository also includes a Python AetherMLStore prototype. They are different storage implementations; choose the Java client when evaluating Aether Engine.

07

Common fixes

When something stops.

SymptomCheck
Connection refusedWait for the daemon’s listening message. Match its port to the Python client. Keep terminal 1 running.
Module not foundRun the pip install command with the same virtual-environment Python used to run the example.
Java version or preview errorCheck java -version and JAVA_HOME. Use JDK 21 and the Gradle task, which supplies preview flags.
Unexpected misses after restartCheck the cache path, source hashes, namespace, transformation fingerprint and library versions.
Wrong sample after editing inputRebuild the content-hash index. Files must stay immutable for the lifetime of an index.
No GPU throughput improvementCheck whether preprocessing was the bottleneck, whether hits occur, and whether request/decoding overhead offsets saved work.
PowerShell rejects a commandUse the Windows command block. Do not paste Bash backslash continuations or Kaggle paths into PowerShell.
