Aether Engine / Developer documentation

Build with Aether.

Aether is an embedded Java database. It lives inside your process, stores byte keys and values through an LSM-oriented engine, and adds a type-safe collection layer with deterministic generated codecs.

Pre-release contract

Aether is currently 0.1.0-SNAPSHOT. Use it for evaluation and development, not durable production data. APIs and persistent formats may change before 1.0.

RecommendedTyped embedded API

Java records, collections, generated codecs, atomic batches, snapshots, and ordered scans.

02

Getting started

Your first persistent collection

This example uses a generated record codec, a stable collection identity, and the persistent typed entry point.

1. Define a record schema

Todo.java
package example;

import io.aetherdb.codec.annotation.AetherRecord;
import io.aetherdb.codec.annotation.AetherMaxLength;

@AetherRecord(version = 1)
public record Todo(
        String id,
        @AetherMaxLength(512) String title,
        boolean completed) {}

2. Open the database and define the collection

Main.java
import io.aetherdb.api.typed.CollectionId;
import io.aetherdb.api.typed.TypedWriteResult;
import io.aetherdb.embedded.typed.AetherEmbedded;
import java.nio.file.Path;

try (var db = AetherEmbedded.open(Path.of("./data/todos"))) {
    var todos = db.defineCollection(
            CollectionId.of("a53f36dd-f4eb-4aac-9fab-8e62e92185d6"),
            "todos",
            String.class,
            Todo.class);

    TypedWriteResult result = todos.put(
            "ship",
            new Todo("ship", "Ship reliably", false));

    if (!(result instanceof TypedWriteResult.Applied applied)) {
        throw new IllegalStateException("write failed: " + result);
    }

    Todo stored = todos.get("ship").requireValue();
    System.out.println(stored.title());
}
Why is the collection UUID explicit?

A record schema ID identifies the value format. A collection ID identifies a logical keyspace. Two collections can intentionally store the same record type, so the current API keeps those identities separate. Generate the UUID once and keep it stable in source.

3. Accept and commit the schema lock

Terminal
./gradlew aetherSchemaInit
./gradlew aetherSchemaAccept
git add aether-schemas

Closing the try-with-resources scope flushes and releases the directory lock. Opening the same path later recovers and reads the same collection.

05

Typed API

Collections and definitions

There are two supported ways to open a collection.

Generated record convenience

defineCollection(CollectionId id, String name, Class<K> keyType, Class<V> valueType)

Resolves a built-in ordered key codec and a processor-generated record codec. It enables point reads, point writes, range scans, and snapshot reads. Supported key classes are currently String, Long/long, and UUID.

Explicit definition

collection(CollectionDefinition<K,V> definition)

Use this for scalar value codecs, custom codecs, or a restricted capability set.

Explicit definition
static final CollectionDefinition<UUID, String> NOTES =
        new CollectionDefinition<>(
                CollectionId.of("7629a9f3-81a7-4346-b68f-cc273e154560"),
                "notes",
                BuiltInKeyCodecs.uuid(),
                BuiltInValueCodecs.utf8String(
                        UUID.fromString("fdd89bea-06ec-4231-bff3-b26047a3b132")),
                Set.of(POINT_READ, POINT_WRITE, RANGE_SCAN));

var notes = db.collection(NOTES);

Registration checks

Opening a definition persists collection metadata. Reusing an ID with a different key codec, schema family, or incompatible fingerprint fails with COLLECTION_SCHEMA_CONFLICT. A newer compatible schema advances the minimum writer version; an older writer is then rejected.

The capability set uses the CollectionCapability enum:

CapabilityWhat it permits
POINT_READRead one complete logical key
POINT_WRITEInsert, replace, or delete one key
RANGE_SCANScan in codec-defined order; requires OrderedKeyCodec
SNAPSHOT_READRead the collection through a stable snapshot
Current enforcement

The embedded adapter actively checks RANGE_SCAN. In 0.1.0-SNAPSHOT, the point-read, point-write, and snapshot flags are descriptive metadata and are not access-control boundaries. Do not use capabilities as a security mechanism.

06

Typed API

Point reads and writes

get(K key)

Returns a ReadResult<V>, never null. Use pattern matching when absence is normal, value() for an Optional, or requireValue() when absence is exceptional.

Read patterns
ReadResult<Todo> result = todos.get("ship");

if (result instanceof ReadResult.Found<Todo> found) {
    System.out.println(found.found().title());
}

Optional<Todo> optional = result.value();
Todo required = result.requireValue(); // throws if absent

put(K key, V value)

Inserts or replaces one value and returns a TypedWriteResult. Inputs must be non-null and encodable within declared bounds.

delete(K key)

Writes a tombstone for the key. Deleting an absent key is still a valid write operation.

07

Typed API

Atomic cross-collection batches

Create batches through the database that will submit them. A batch may target several collections owned by that same writable database. All operations receive one contiguous sequence range and commit atomically.

Atomic relationship update
TypedWriteBatch batch = db.batch()
        .put(profiles, user.id(), user)
        .put(handles, user.handle(), user.id())
        .delete(pendingInvites, user.email());

TypedWriteResult result = db.write(batch);
if (result instanceof TypedWriteResult.Applied applied) {
    System.out.println("Committed " + applied.operationCount() + " changes");
}
  • A batch is one-shot; submitting it twice throws.
  • Collections from another database or snapshot-bound collections are rejected.
  • An empty typed batch returns Rejected(commandId, "EMPTY_BATCH", false).
  • The underlying limits are 10,000 operations and 32 MiB encoded size.
08

Typed API

Stable snapshots

A snapshot pins the database’s current sequence. Reads through snapshot-bound collections continue to observe that sequence even after later writes commit.

Consistent read view
try (TypedAetherSnapshot snapshot = db.snapshot()) {
    var stableTodos = snapshot.collection(todos.definition());

    Todo before = stableTodos.get("ship").requireValue();
    todos.put("ship", completedVersion);
    Todo stillBefore = stableTodos.get("ship").requireValue();
}

Snapshot collections are read-only: put, delete, and use in a writable batch fail. Always close snapshots promptly; they pin historical visibility and the engine allows at most 1,024 active snapshots.

09

Typed API

Ordered scans

List<TypedKeyValue<K,V>> scanAll()

scanAll() materializes every visible entry in key order and returns an immutable list. It requires the RANGE_SCAN capability and an OrderedKeyCodec.

Memory behavior

The typed method materializes its complete result. For large or bounded ranges, use the byte API’s closeable cursor until a typed streaming cursor is added.

String keys use lexicographic UTF-8 byte order, signed longs use an order-preserving sign-bit transform, and UUIDs use unsigned most-significant then least-significant component order.

10

Typed API

Write outcomes

Do not reduce a typed write result to a boolean. Its three variants describe whether retrying is safe.

APPLIED

Applied

The mutation committed. Includes command ID, operation count, and allocated sequence range.

REJECTED

Rejected

No uncertain commit occurred. Inspect the stable reason and retryable flag.

UNCERTAIN

Indeterminate

The caller cannot know the final commit status. Follow retryInstructions; never blindly duplicate the command.

Exhaustive handling
switch (result) {
    case TypedWriteResult.Applied applied ->
            acknowledge(applied.commandId());
    case TypedWriteResult.Rejected rejected ->
            handleRejection(rejected.reason(), rejected.retryable());
    case TypedWriteResult.Indeterminate uncertain ->
            reconcile(uncertain.commandId(), uncertain.retryInstructions());
}
Current adapter behavior

The embedded typed adapter currently returns Applied for successful writes and Rejected("EMPTY_BATCH") for an empty batch. Persistent write failures still propagate as exceptions rather than being translated to Indeterminate. The variant is part of the public result model, but complete exception-to-outcome mapping is not implemented yet.

Schemas & codecs

Generated record codecs

The annotation processor turns an @AetherRecord into a deterministic AER1 value codec, canonical descriptor, SHA-256 fingerprint, and runtime provider registration. Runtime discovery uses ServiceLoader; descriptor fingerprints are verified while the registry loads.

GeneratedCodecs.forRecord(Todo.class) is called by defineCollection. It fails with CODEC_NOT_AVAILABLE if the record is unannotated, the processor was not configured, or generated provider resources are absent.

Generated artifactPurpose

Canonical descriptorStable machine-readable schema structure
SHA-256 fingerprintDetect descriptor/code divergence

Schemas & codecs

Schema annotations

@AetherRecord(version)
Declares a durable record family and positive writer version. schemaId may be explicit; otherwise the schema tool assigns it through the committed lock.
@AetherField
Controls stable field identity, records the prior name for a rename, and declares optional or nullable semantics.
@AetherMaxLength
Bounds UTF-8 bytes or collection element count for a variable-length component.
@AetherMaxEntries
Bounds decoded elements or entries in a persistent container.
@AetherEnum
Marks an enum as persistent. Every constant needs an explicit positive @AetherEnumValue.
Structured record
@AetherEnum
public enum Status {
    @AetherEnumValue(1) PENDING,
    @AetherEnumValue(2) POSTED
}

@AetherRecord(version = 2)
public record LedgerEntry(
        UUID accountId,
        long amountMinor,
        @AetherMaxLength(3) String currency,
        @AetherField(previousName = "state") Status status,
        Instant bookedAt) {}

Schemas & codecs

Schema lock workflow

1Propose./gradlew aetherSchemaInitFirst lock only
2Reviewbuild/aether-schema/proposalNo source mutation yet
3Accept./gradlew aetherSchemaAcceptWrites aether-schemas/
4Commitgit add aether-schemasDurable identity in VCS

For later intentional changes, increment the record version and run aetherSchemaUpdate, review the proposal, then run aetherSchemaAccept. Normal compilation and aetherSchemaCheck only verify; they do not silently rewrite committed locks.

Never regenerate identities casually

The lock contains schema UUIDs, stable field IDs, bounds, retired identities, and descriptor fingerprints. Deleting it can make existing data undecodable or misidentified.

14

Schemas & codecs

Evolution rules

Aether compares stored collection metadata with the current generated descriptor when a collection opens. Compatible upgrades advance the collection’s minimum writer version.

ChangeRequired actionRisk
Add a fieldIncrement version; make omission from older payloads valid where appropriateOld data has no value for the new field
Rename a fieldUse @AetherField(previousName="oldName")A rename without history can look like remove + add
Remove a fieldRetire its stable identity through the accepted proposalNever reuse the field ID
Change boundsReview compatibility and generated proposalNarrower bounds may reject existing values
Change schema UUIDTreat as a distinct schema familyExisting collection metadata conflicts

Once a newer writer registers a compatible upgrade, an older writer version is rejected for writes with OLDER_WRITER_REJECTED. This prevents old code from reintroducing a superseded format.

Core byte API

AetherDatabase

The core contract stores arbitrary byte-array keys and values. Implementations defensively copy inputs and outputs, so callers retain ownership of their arrays.

Byte-oriented database
import io.aetherdb.engine.Aether;
import java.nio.charset.StandardCharsets;
import java.nio.file.Path;

try (var db = Aether.open(Path.of("./data/raw"))) {
    byte[] key = "user:42".getBytes(StandardCharsets.UTF_8);
    db.put(key, "Ada".getBytes(StandardCharsets.UTF_8));

    LookupResult result = db.get(key);
    if (result.isFound()) {
        System.out.println(new String(result.value(), StandardCharsets.UTF_8));
    }

    db.delete(key);
}

AetherException is the runtime base class for Aether contract failures. Its specialized public variants are:

put(key, value)
Insert or replace one value using default write options.
delete(key)
Delete one key by writing a tombstone.
get(key[, snapshot])
Return LookupResult.found or the ordinary logical-absence result.
write(batch[, options])
Atomically apply an ordered one-shot batch.
scan(...)
Create a closeable cursor over a half-open byte-key range.
newSnapshot()
Capture the current visibility sequence.
17

Core byte API

WriteBatch

A raw batch is ordered, bounded, defensively copied, and one-shot. Duplicate keys are permitted; their order within the atomic command is preserved.

Explicit batch
try (WriteBatch batch = new WriteBatch()) {
    batch.put(firstKey, firstValue)
         .delete(oldKey)
         .put(secondKey, secondValue);

    WriteResult result = db.write(batch, WriteOptions.defaults());
    System.out.printf("sequences %d..%d%n",
            result.firstSequence(), result.lastSequence());
}

Application code normally interacts with OPEN and a terminal state. The engine uses SEALED, SUBMITTED, SUCCEEDED, FAILED, and INDETERMINATE to track whether a retry can be known safe.

32 MiBmaximum encoded batch
64 KiBmaximum key
16 MiBmaximum value

Core byte API

Raw snapshots

newSnapshot() returns an immutable database-owned visibility boundary with a local handle ID and highest visible sequence. Pass it back only to the database that created it.

  • A closed snapshot is invalid.
  • A snapshot from another database is rejected.
  • Closing the database invalidates its owned handles.
  • Close snapshots promptly to avoid pinning historical versions.
19

Core byte API

Cursors and ranges

scan(startInclusive, endExclusive) uses a half-open byte range. scanAll() spans all visible keys. Snapshot overloads preserve the snapshot’s sequence.

Range scan
try (AetherCursor cursor = db.scan(prefix, prefixEnd)) {
    while (cursor.next()) {
        consume(cursor.key(), cursor.value());
    }
}

A cursor starts before its first entry. Call next() before key() or value(); both accessors return defensive copies and throw if the cursor is not positioned. Always close the cursor.

20

Core byte API

Write options and results

new WriteOptions(durabilityMode, admissionTimeout, failFastOnBackpressure)

WriteOptions.defaults() selects GROUP_SYNC, a 30-second admission timeout, and waiting rather than immediate rejection during slowdown pressure.

WriteResult reports operation count, first/last allocated sequence, requested durability, and whether the implementation actually performed a storage barrier. In-memory engines report no performed barrier.

Admission is not commit

The timeout and fail-fast flag control waiting for write-path capacity. They do not convert an outcome beyond the submission uncertainty boundary into a known failure.

Operations

Durability modes

ModeReturn boundaryTrade-off
ASYNC_WALAfter append to the process-visible WAL bufferLowest barrier cost; no requested storage sync before return
GROUP_SYNCAfter a shared storage synchronization barrierDefault; amortizes force cost across admitted writes
SYNCRequests a dedicated durability barrierStrongest API request; intended for an isolated barrier

The persistent engine writes WAL records before publishing visibility. The crash benchmark uses acknowledged durable marker writes followed by Runtime.halt, then reopens and validates every prior marker.

Current group-commit behavior

The DurabilityMode contract distinguishes SYNC from GROUP_SYNC. The current persistent implementation performs one WAL force for a commit group whenever any request requires synchronization, so SYNC is presently coalesced rather than given a separate force. Treat that distinction as unfinished in this snapshot.

Operations

Lifecycle and locking

EphemeralAether.openInMemory()

New deterministic in-memory database. All contents disappear on close.

PersistentAether.open(path)

Create or recover a local database and acquire its process-exclusive writer lock.

TypedAetherEmbedded.open(path)

Own the underlying database through the type-safe adapter.

InstrumentedAether.openWithMetrics(path)

Own a persistent database through a metered decorator.

  • Use try-with-resources for databases, snapshots, cursors, and raw batches.
  • Do not open the same directory concurrently in an application and Workbench.
  • instrument(existing) and AetherEmbedded.adapt(existing) transfer close ownership to the returned wrapper.
  • Operations after close fail; owned snapshots and cursors become invalid.
23

Operations

Runtime metrics

The metered decorator records PUT, DELETE, GET, SCAN creation, SNAPSHOT creation, and WRITE submission. It has no external monitoring dependency.

Collect metrics
try (var db = Aether.openWithMetrics(path)) {
    db.resetMetrics();
    runWorkload(db);

    OperationMetrics reads = db.metrics().operation(DatabaseOperation.GET);
    System.out.printf(
            "rate=%.0f/s p50=%.3fms p95=%.3fms p99=%.3fms errors=%d%n",
            reads.operationsPerSecond(),
            reads.p50LatencyNanos() / 1_000_000.0,
            reads.p95LatencyNanos() / 1_000_000.0,
            reads.p99LatencyMillis(),
            reads.errors());
}

Counts, errors, average/min/max, and throughput cover the complete interval since creation or reset. Percentiles use the most recent bounded 16,384-sample reservoir per operation, preventing telemetry memory from growing with uptime. metrics() returns an immutable point-in-time snapshot.

Operations

Failure model

DatabaseOpenException
Persistent initialization, directory locking, recovery, or opening I/O failed.
AetherClosedException
An operation targeted a closed engine, batch, or handle.
SnapshotException
A snapshot was closed, foreign to the database, or otherwise invalid.
SnapshotLimitExceededException
The engine already owns its maximum active snapshot handles.
SequenceExhaustedException
No further positive sequence can be allocated safely.
IllegalArgumentException
Invalid bounds, codec metadata, ownership, collection conflict, or unsupported Java type.
UnsupportedOperationException
A collection lacks the requested capability or a snapshot-bound collection was used for writes.

Typed write admission outcomes use TypedWriteResult rather than exceptions. Exceptions still represent contract violations, invalid ownership, schema conflicts, closed resources, or unrecoverable engine failures.

How persistence works

01Write admissionValidate bounds and pressure policy
02WALEncode atomic group and perform requested barrier
03MemTablePublish ordered sequence-visible entries
04SSTableRestart blocks, Bloom filter, index, properties, checksums
05ManifestAtomically publish the current file inventory

On open, the persistent engine validates identity and metadata, recovers the durable inventory, and replays required state. The current implementation materializes its checkpoint into heap during open; measured point reads afterward are therefore heap-resident.
